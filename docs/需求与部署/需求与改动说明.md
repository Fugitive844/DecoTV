# DecoTV 图片预览与前端性能需求

## 问题与目标

线上约配置 156 个视频源。搜索及视频源管理页面在大量结果、滚动、检测和静置时出现浏览器 CPU/GPU 持续占用；手机访问时发热。部分资源能播放视频，但封面显示“暂无封面”。视频与封面来自不同 URL，视频可播放不能证明封面地址可访问。

目标是让浏览器从同源接口取得可识别的图片，完整保留上游图片协议、端口和查询参数；降低搜索结果计算、管理列表渲染、封面解码，以及装饰动画和滤镜带来的压力。保留播放、源管理、筛选、聚合与正常加载反馈。

图片代理支持 JPEG、PNG、GIF、WebP、AVIF、SVG、BMP、ICO 的签名识别。能识别返回格式，不代表浏览器必然支持该格式，也不代表 Sharp 必然能转码所有编码变种；常见静态格式尽量生成 WebP 缩略图，动画及不支持转码的情况保留原图。接口拒绝返回 HTML 的假图片、私网目标、超限响应等。失效源、上游 404、权限限制和浏览器不支持的原始格式仍可能产生占位图。

这次普通封面改为服务端下载再返回给浏览器，因此封面下载会使用部署服务器的网络。它与 m3u8 广告过滤、播放代理、直播代理和 TMDB API 代理分别是不同功能；不能由“图片预览正常”推断视频走直连或代理。

## 现有 Nginx 的处理边界

线上站点此前已有 Nginx/Lua 图片兼容处理。新源码普通封面使用 `/api/image-proxy`，生产部署应先保留现有站点配置，验证实际请求路径、JS/CSS 响应与图片解码，再判断旧处理是否还需要。尚未在新镜像下验证这组组合，不在此次文档整理中删除或调整 Lua。

站点配置变更范围仍是 `tv.gzsuy.com` 对应配置；不能顺手改全局 `nginx.conf` 或其他站点。生产已有的源、用户、数据库密码、端口和数据卷都不由本地测试配置覆盖。

## 验收要求

1. 搜索结果数量、聚合切换、筛选和末尾结果可达；滚动追加不跳回顶部。
2. 156 个视频源的管理页分页、跨页勾选、全选和检测结束状态正常。
3. 覆盖 HTTP、HTTPS、非标准端口、查询参数、重定向、旧 wsrv 地址、错误 MIME、超时和伪图片；结合前端 `naturalWidth` 验证实际解码。
4. 搜索结束、封面加载完、菜单关闭后，检查装饰动画、滤镜及后台重复请求；真实加载和播放开销分别记录。
5. 用相同数据与生产构建比较修改前后页面 CPU/GPU；手机真机发热、耗电需单独复测。
6. 测试报告只记录文字与指标，不放截图。线上未筛选源仅检查响应和解码元数据，不查看敏感图片内容。

本地图片相关单测 26/26 通过，浏览器已验证封面加载及虚拟滚动。类型检查与修改文件的 ESLint 检查通过。空闲页面装饰动画/滤镜检查通过；CPU/GPU 降幅与手机温度尚未量化，不能写成已经解决所有终端发热。详见[测试交接](测试交接.md)。
