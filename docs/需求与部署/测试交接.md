# DecoTV 本地测试交接

本次验证用户 fork `https://github.com/Fugitive844/DecoTV` 的封面修复和前端 CPU 优化。该文档记录本地验证，生产状态见[发布状态与接手事项](发布状态与接手事项.md)。原有 `docker-compose.yml` 和 `.env.local` 不作为测试配置，也不覆盖。部署与更新方法见[Docker 镜像推送与服务器部署](Docker镜像发布与服务器部署.md)。

## 环境与隔离

- Windows、Node.js 22 或更高版本（本次安装使用 Node.js 24）、pnpm **10.14.0**、Docker Desktop。
- 数据库使用 Docker 内的 **Apache Kvrocks**，与线上同一数据库类型；创建独立容器、独立卷和强密码，不连接生产数据库。
- 数据库仅映射 `127.0.0.1:16379`，容器内部为 `6666`。开发网站仅监听本机回环地址 `localhost:3000`。
- 测试配置保存在 Git 忽略的 `.env.development.local`。密码不要复制到报告、日志或 Git。
- 安装依赖使用项目固定 pnpm 版本；不要使用 pnpm 11 重建本项目依赖。

```powershell
pnpm install --frozen-lockfile
docker compose --env-file .env.development.local -f docker-compose.local.yml up -d
pnpm dev:local
```

数据库配置至少包括 `NEXT_PUBLIC_STORAGE_TYPE=kvrocks`、`KVROCKS_URL=redis://:密码@127.0.0.1:16379`，以及开发站长 `USERNAME`、`PASSWORD`、`AUTH_SECRET`。`.env.development.local` 中配置 `NEXT_PUBLIC_AUTH_MODE=password`，清空其他数据库 URL，避免已有 `.env.local` 引入生产连接。配置创建后重启开发服务使其生效。

新接手者在项目根目录创建 `.env.development.local`，替换下面所有占位值；已有本机测试环境继续使用现存配置，不重新生成密码：

```dotenv
NEXT_PUBLIC_STORAGE_TYPE=kvrocks
NEXT_PUBLIC_AUTH_MODE=password
USERNAME=local-admin
PASSWORD=填写独立测试站长密码
AUTH_SECRET=填写独立随机签名密钥
KVROCKS_PASSWORD=填写独立数据库密码
KVROCKS_URL=redis://:填写同一个数据库密码@127.0.0.1:16379
REDIS_URL=
UPSTASH_URL=
UPSTASH_TOKEN=
```

可以运行 `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` 生成十六进制随机值，分别用于上述密码和密钥。数据库 URL 的密码必须与 `KVROCKS_PASSWORD` 相同；十六进制值避免 URI 特殊字符转义问题。本地实际凭据见 `测试交接-本机私密.md`，不要把该文件提交。

启动脚本目前报错文字中的“测试交接.md”指本目录的交接文档。Windows 上必须使用 `pnpm dev:local` 显式加载配置，避免系统 `USERNAME` 覆盖站长账号；脚本使用 Webpack 规避 Sharp 外部依赖的本地 Turbopack 符号链接权限问题。

视频筛选必须同时满足：`is_adult` 明确为 false、名称没有成人特征、分类接口正常返回 JSON 且没有成人分类。含“伦理”等分类的普通资源站也排除；不可访问或无法确认的源排除。只读取源名称、分类，不打开封面或视频内容。

## 功能测试

1. 访问本地 `/admin`，使用测试站长登录，确认没有“本地存储模式”提示，即已经使用 Kvrocks。
2. 导入合并配置，重新请求 `/api/admin/config`，确认 3 个视频源、26 个直播源；刷新浏览器、重启开发服务后数量保持不变。
3. 搜索正常影视关键词，例如“流浪地球”，确认流式结果、聚合切换、年份/清晰度筛选、分页或滚动加载可用；最终数量与后端结果一致。
4. 用正常 API 检测视频源；确认结果更新及完成提示正确，关闭/离开页面后 EventSource 和定时器停止，不继续重复请求。
5. 直播页确认源列表可见，选择一个源验证频道解析。上游不通需单独记录状态，不能将“导入成功”写成“所有节目可播放”。

## 封面测试及隐私要求

本轮用户允许查看已筛选源的封面进行显示与布局验证；**测试报告不包含截图，也不添加截图附件**。报告记录请求状态、Content-Type、文件签名、字节长度，以及前端 `img.complete` / `naturalWidth` / `currentSrc` 等加载元数据。

必须覆盖：HTTP 源、HTTPS 源、非标准端口、带查询参数地址、旧 wsrv 地址、重定向、错误 MIME 的真实图片、返回 HTML 的假图片、404、超时、私网地址。

格式覆盖 JPEG、PNG、GIF、WebP、AVIF、SVG（含 XML/BOM）、BMP、ICO。静态常用格式带 `w` 时应生成 WebP 缩略图；动画和其他格式保留原字节。格式被识别不代表浏览器支持所有编码变体，必须检查浏览器解码结果。

合格标准：普通封面的首选请求为本站 `/api/image-proxy`，明确的 HTTP/HTTPS 协议不会被删除或改写；失败时尝试候选封面，最后显示占位图。聚合组首个源封面失效时能尝试同组其他封面。上游真实 404 无法恢复，要记录为源数据问题。

## CPU 与大列表测试

- 搜索 SSE 结果约每 250ms 批量合并，避免每个源都执行完整计算；只计算当前显示模式的筛选排序。
- 触底加载从首批结果开始使用虚拟列表和实际 body 滚动容器，避免 48→96 项切换渲染方式造成滚动跳回顶部；分页模式每页 48 项使用普通列表。测试滚动到底、继续加载、聚合切换、分页与返回顶部，不能只验证首屏。
- 视频源管理每页最多 50 行；全选、批量操作和保存排序仍针对原有完整数据。必须核对跨页选中和排序持久化。
- 检测结果按约 200ms 批量更新；视频源、分类、直播源行使用稳定的组件类型，父组件更新时不应整批卸载、重建拖拽行。
- 全站默认静态背景；SSR 即启用轻量模式，移除大面积动画混合层和 SVG 噪点。品牌渐变、状态脉冲等装饰循环停止；导航栏玻璃模糊关闭，真正的加载指示和播放逻辑保留。

性能实测必须使用同一浏览器、同一数据量、同一操作、同一构建模式比较修改前后；记录空闲 30 秒、搜索期间、检测期间的平均/峰值 CPU、长任务数量、DOM 行/卡片数量。开发编译占用与浏览器 CPU 分开记录。3 个严格筛选源不能用于声称已证明 156 个实际源下的 CPU 改善；大列表可使用独立、明确标注的非成人模拟数据，结束后恢复正式导入配置。

## 停止与数据保留

## GPU 与手机发热复测方式

ChatGPT 内置浏览器的渲染进程会计入 Windows 任务管理器中的 ChatGPT 分组，因此该分组的高占用确实包含本次正在测试的 DecoTV 页面；不能用分组名称排除前端压力。同时，此数值叠加桌面应用其他进程、Next.js 开发调试和热更新相关开销，尚未拆分出单个页面占用。可使用独立 Edge / Chrome 测试本地站点，通过浏览器任务管理器确认对应标签页 CPU；显卡占用需在其他图形负载停止后进行同场景对照。

分别记录页面加载完成后静置 30 秒、搜索过程中、连续滚动时、视频播放时的状态。静置测试要求封面已加载、搜索已结束、菜单关闭；记录仍在运行的 CSS 动画及滤镜。播放视频时的解码与合成开销单独记录。

手机真机温度、耗电和浏览器 CPU/GPU 尚未测试。线上站点尚未部署本次源码修改，所以手机继续访问线上时仍使用旧前端。桌面窄视口测试仅代表布局验证，不能写成已验证真机发热改善。报告只写文字和指标，不附截图。
